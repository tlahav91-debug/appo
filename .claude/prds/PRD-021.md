# PRD — Home Screen v5 Redesign
**ID:** PRD-021
**Sprint block:** BLOCK 2
**Priority:** P1
**Author:** PM Agent
**Date:** 2026-04-26

## Problem / Why
The current HomeScreen is a minimal placeholder. The AppLoop v5 design shows a rich, gamified home experience: hero carousel with auto-scroll, live events row, drama grid with progress indicators, and gamification rails. This is the first screen players see — it must match the design to deliver the intended experience.

## Success metrics
- Home screen matches AppLoop v5 design visually
- Hero carousel auto-scrolls every 4 seconds
- Live events row shows active events (Lava Quest, Race, Daily)
- Drama grid shows real series from DB
- Journey and Events cards accessible from Home

## Scope (in)
- Hero carousel: auto-scrolling PageView of featured dramas (top 5 by view_count); each card shows full-bleed gradient poster, title, hook text, episode count, "Watch Now" CTA button (pink gradient, raised game style); PageIndicator dots below
- Live Events row: horizontal scroll, EventsCard and JourneyCard (from PRD-018 deliverables) shown first; then active quest cards (Lava Quest active indicator if quest is active, Race card if race is active) — each taps to respective screen
- Drama grid: 3-column grid below the rows; shows series posters with title, episode count, VIP lock badge if drama_pass_active=false and series requires pass; each taps to DramaDetailScreen
- Continue Watching strip (if watch_progress rows exist): shows as a horizontal scroll above the grid ("Continue Watching" header + drama cards with progress bar); reads from watch_progress via a FutureProvider; only shown if user has in-progress dramas
- Club activity strip: small horizontal strip showing "Your Club: [name] — 🔥 N watching now" if user is in a club; reads from existing club provider
- All use existing design tokens from tokens.dart (bgDeep, bgCard, pink, gold, textCol, textDim, pinkFull gradient, etc.)
- No hardcoded hex colours anywhere

## Scope (out)
- No personalised drama recommendations (uses view_count ordering)
- No algorithm-driven feed
- No social feed / drama comments on Home
- No ads placement yet

## Data model
Reads existing tables: series (poster_url, title, view_count, hook_text?, episode_count, requires_pass), watch_progress (from PRD-019), watch_clubs (from PRD-014). If hook_text column doesn't exist on series, use subtitle or first 80 chars of description, or omit gracefully.

## API / Edge Functions
None new. Reads via existing Supabase client.

## Flutter screens / components
- `lib/features/profile/presentation/home_screen.dart` — full rewrite
- `lib/features/profile/application/home_provider.dart` — FutureProvider for featured series list + drama grid list (two separate queries)
- Reuse: EventsCard, JourneyCard (from PRD-018)
- Reuse: PosterCard widget
- Reuse: watch_progress provider (from PRD-019)
- Reuse: club provider (from PRD-014)

## Economy / Monetisation notes
Hero carousel "Watch Now" CTA is primary drama-start driver → energy spend. Continue Watching strip drives return energy spend. VIP lock badge on grid items is passive Drama Pass conversion prompt.
