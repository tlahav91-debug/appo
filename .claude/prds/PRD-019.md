# PRD — Continue Watching / My List
**ID:** PRD-019
**Sprint block:** BLOCK 2
**Priority:** P0
**Author:** PM Agent
**Date:** 2026-04-26

## Problem / Why
Players who close the app mid-series have no way to resume. Without "Continue Watching," standard streaming benchmarks show 40–60% drop-off on re-open. This is the single highest-leverage retention feature missing from the app.

## Success metrics
- Players can resume any in-progress episode from My List → Continue tab
- Progress heartbeat recorded every 15 seconds of watch time
- Saved dramas persist across sessions
- History shows last 20 watched episodes

## Scope (in)
- New DB table: `watch_progress(id UUID PK, user_id UUID FK, series_id UUID FK, episode_id UUID FK, progress_pct SMALLINT 0–100, completed BOOLEAN DEFAULT false, last_watched_at TIMESTAMPTZ DEFAULT now())`
  - UNIQUE(user_id, episode_id) — upsert on conflict
  - RLS: authenticated user can SELECT/INSERT/UPDATE own rows only; no service_role bypass needed (soft data)
  - Index on (user_id, last_watched_at DESC) for history queries
- New DB table: `saved_dramas(id UUID PK, user_id UUID FK, series_id UUID FK, saved_at TIMESTAMPTZ DEFAULT now())`
  - UNIQUE(user_id, series_id)
  - RLS: authenticated can SELECT/INSERT/DELETE own rows
- Edge Function: `record-watch-progress` — POST + JWT auth
  - Body: `{ episode_id, series_id, progress_pct, completed? }`
  - Upserts watch_progress row, sets last_watched_at = now()
  - Returns `{ ok: true }`
- Edge Function: `toggle-saved-drama` — POST + JWT auth
  - Body: `{ series_id }`
  - If row exists → DELETE (unsave); if not → INSERT (save)
  - Returns `{ saved: boolean }`
- Flutter: `MyListScreen` with 3 tabs:
  - **Continue** — FutureProvider fetches watch_progress rows WHERE completed=false, ordered by last_watched_at DESC, LIMIT 20; shows drama poster + episode title + LinearProgressIndicator (progress_pct/100); "Jump In" CTA button → navigates to episode player
  - **Saved** — FutureProvider fetches saved_dramas joined to series; 3-column poster grid; long-press or X to unsave
  - **History** — FutureProvider fetches watch_progress ordered by last_watched_at DESC LIMIT 50; list rows with poster thumbnail, episode title, completion badge if completed=true
- Flutter: `WatchProgressService` — singleton, exposes `recordProgress(episodeId, seriesId, progressPct, {completed})` → calls `record-watch-progress` Edge Function fire-and-forget; called from episode player on 15s heartbeat and on episode end
- Flutter: `SavedDramaService` — exposes `toggle(seriesId)` → calls `toggle-saved-drama`; returns new saved state
- Flutter: bookmark icon button on DramaDetailScreen/EpisodePlayer that calls SavedDramaService.toggle()

## Scope (out)
- No offline download
- No sync across devices beyond what Supabase realtime gives for free
- No recommendation engine based on history
- No watch_progress realtime subscription (polling on tab focus is fine)

## Data model
| Table | Key columns | RLS |
|-------|-------------|-----|
| watch_progress | id, user_id, series_id, episode_id, progress_pct SMALLINT, completed BOOL, last_watched_at TIMESTAMPTZ | SELECT/INSERT/UPDATE WHERE user_id = auth.uid() |
| saved_dramas | id, user_id, series_id, saved_at TIMESTAMPTZ | SELECT/INSERT/DELETE WHERE user_id = auth.uid() |

## API / Edge Functions
| Function | Method | Auth | Request | Response |
|----------|--------|------|---------|----------|
| record-watch-progress | POST | JWT (user) | { episode_id, series_id, progress_pct, completed? } | { ok: true } |
| toggle-saved-drama | POST | JWT (user) | { series_id } | { saved: boolean } |
